# 导入和校验已有 MySQL 数据

## 方案

工具从 MySQL InnoDB 只读快照按主键流式读取物理表，使用 PostgreSQL `COPY` 保留原 ID、分片位置和加密字段。目标事务持有表锁，并要求所有应用表为空。转换统计列名和首访布尔值后逐表对比行数及内容摘要。identity 序列取源库下一号和最大已有 ID 加一中的较大值。所有表完成验证后统一提交。`--verify-only` 支持独立校验。

## 验证

- 启动迁移前的 MySQL 版应用，创建用户、分组、短链、API Token 并通过 Redis Stream 写入统计。另写入包含中文、换行和表情的 AI 会话消息。
- 使用 PostgreSQL 19.0 导入并独立复核 62 张表共 26 条记录。源库下一号大于最大已有 ID 的测试表保留了该下一号。
- 人为拒绝最后阶段的写入，确认前面的行和序列调整均回滚。另验证非空目标会拒绝导入、行数相同但内容不同会拒绝通过校验。
- 沿用测试 Redis 和原 AES 密钥启动新版，验证旧会话、API Token 和用户资料解密。清除跳转缓存后，确认旧短链从 PostgreSQL 读取并正常跳转，历史统计可读且新访问继续累加。
